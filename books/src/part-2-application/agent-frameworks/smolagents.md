## Overview

smolagents is a lightweight library from HuggingFace for building code-first AI agents. The entire agent logic fits in approximately one thousand lines of code with minimal abstractions, making it straightforward to understand, extend, and debug. Rather than forcing agents to express actions through JSON blobs or structured text, smolagents encourages a code-first paradigm where agents write Python code to compose tools, use loops and conditionals, and chain function calls naturally.

The library is model-agnostic, modality-agnostic, and tool-agnostic: it works with HuggingFace Inference Providers, OpenAI, Anthropic, local models, and more. It handles text, vision, video, and audio. It connects to Model Context Protocol (MCP) servers, LangChain tools, and HuggingFace Hub Spaces as tools.

## Core Concepts

**Code Agents** are the central idea. A CodeAgent writes executable Python code as its reasoning output rather than emitting structured JSON tool calls. This means the agent can naturally compose operations (nesting function calls, iterating with loops, branching with conditionals) in ways that JSON-based tool calling cannot express as cleanly.

**Tool-Calling Agents** provide a traditional paradigm for models that work better with structured JSON or text-based tool invocations. ToolCallingAgent follows the conventional request-response tool-calling pattern.

**Tools** are callable objects that agents invoke. smolagents supports native tools, MCP server tools, LangChain tools, and HuggingFace Hub Spaces used directly as tools.

**Models** are the underlying Large Language Models (LLMs) driving agent reasoning. smolagents abstracts the model layer so that switching between providers requires changing a single line of configuration.

**Hub Integration** allows sharing and loading agents and tools to and from the HuggingFace Hub as Gradio Spaces, enabling community reuse and collaboration.

## Architecture

smolagents follows a minimal architecture with three main layers:

**Agent Layer** contains CodeAgent and ToolCallingAgent. Each agent holds a model reference and a list of tools. On each step, the agent sends the current conversation (system prompt, user query, prior steps) to the model, parses the response, executes actions, and appends observations back into the conversation for the next step.

**Model Layer** provides a unified interface across providers. InferenceClientModel connects to HuggingFace Inference Providers, LiteLLMModel wraps OpenAI/Anthropic/other providers through LiteLLM, and TransformersModel runs models locally.

**Tool Layer** wraps callable functions with metadata (name, description, input/output schemas). Tools can be native Python functions decorated as tools, MCP server endpoints, LangChain tools, or Hub Spaces.

**Secure Execution** for CodeAgent is handled through sandboxed environments. Code generated by the agent runs inside Modal, Blaxel, E2B, or Docker containers to prevent arbitrary code execution on the host system.

## Key Features and Functionality

- **Code-First Agents**: Agents write Python code for actions, enabling natural composability through function nesting, loops, and conditionals
- **Secure Code Execution**: Sandboxed execution via Modal, Blaxel, E2B, or Docker
- **Tool-Calling Agents**: Traditional JSON/text-based tool-calling paradigm for compatibility
- **Hub Integration**: Share and load agents and tools to/from HuggingFace Hub as Gradio Spaces
- **Model-Agnostic**: HuggingFace Inference Providers, OpenAI, Anthropic, LiteLLM, Transformers, Ollama
- **Modality-Agnostic**: Text, vision, video, and audio support
- **Tool-Agnostic**: Native tools, MCP servers, LangChain tools, Hub Spaces as tools
- **CLI Tools**: `smolagent` and `webagent` command-line utilities
- **Minimal Codebase**: Core agent logic in approximately one thousand lines of code

## Use Cases

- **Research Assistants**: Agents that search the web, read documents, and synthesize answers using code-based reasoning
- **Data Analysis Pipelines**: Agents that write and execute data processing code with loops and conditionals over datasets
- **Multi-Modal Workflows**: Agents that process images, audio, or video alongside text
- **Tool Orchestration**: Composing multiple tools (APIs, databases, file systems) through natural code rather than rigid JSON schemas
- **Rapid Prototyping**: Building agent prototypes quickly with minimal boilerplate due to the lightweight design
- **Community Tool Sharing**: Publishing reusable tools and agents to the HuggingFace Hub for others to load and extend

## API Reference Summary

### Agent Classes

- `CodeAgent(tools, model, ...)`: Agent that writes Python code to execute actions
- `ToolCallingAgent(tools, model, ...)`: Agent that uses structured JSON tool calls
- `agent.run(task)`: Execute an agent on a task string and return the result

### Model Classes

- `InferenceClientModel(model_id="...")`: Connect to HuggingFace Inference Providers
- `LiteLLMModel(model_id="...")`: Connect to OpenAI, Anthropic, and other providers via LiteLLM
- `TransformersModel(model_id="...")`: Run models locally using the Transformers library

### Built-in Tools

- `DuckDuckGoSearchTool()`: Web search via DuckDuckGo (included with the toolkit extra)

### Hub Operations

- Share agents and tools to the HuggingFace Hub as Gradio Spaces
- Load community-published agents and tools from the Hub

## Configuration and Customization

### Model Configuration

```python
from smolagents import InferenceClientModel

# HuggingFace Inference (default)
model = InferenceClientModel()

# Specific HuggingFace model
model = InferenceClientModel(model_id="meta-llama/Llama-3-70B-Instruct")
```

```python
from smolagents import LiteLLMModel

# OpenAI via LiteLLM
model = LiteLLMModel(model_id="gpt-4")

# Anthropic via LiteLLM
model = LiteLLMModel(model_id="anthropic/claude-sonnet-4-20250514")
```

```python
from smolagents import TransformersModel

# Local model
model = TransformersModel(model_id="HuggingFaceTB/SmolLM-135M-Instruct")
```

### Agent Configuration

```python
from smolagents import CodeAgent

agent = CodeAgent(
    tools=[],          # list of Tool objects
    model=model,       # any model instance
)
```

## Integration Patterns

### MCP Server Tools

smolagents can connect to MCP servers to use their tools directly within agents, enabling access to external systems and data sources exposed through the Model Context Protocol.

### LangChain Tools

Existing LangChain tools can be wrapped and used as smolagents tools, enabling reuse of the LangChain ecosystem without rewriting tool definitions.

### Hub Spaces as Tools

HuggingFace Hub Spaces (Gradio apps) can be used as tools, allowing agents to call community-built applications as part of their reasoning pipeline.

### Custom Tools

Define custom tools as Python functions with appropriate metadata for the agent to discover and invoke during execution.

## Examples

### Basic Code Agent

```python
from smolagents import CodeAgent, InferenceClientModel

model = InferenceClientModel()
agent = CodeAgent(tools=[], model=model)
result = agent.run("Calculate the sum of numbers from 1 to 10")
```

### Agent with Web Search

```python
from smolagents import CodeAgent, InferenceClientModel, DuckDuckGoSearchTool

agent = CodeAgent(
    tools=[DuckDuckGoSearchTool()],
    model=InferenceClientModel(),
)
result = agent.run("What is the current weather in Paris?")
```

### Using OpenAI via LiteLLM

```python
from smolagents import CodeAgent, LiteLLMModel

model = LiteLLMModel(model_id="gpt-4")
agent = CodeAgent(tools=[], model=model)
result = agent.run("Explain the Fibonacci sequence")
```

### Tool-Calling Agent

```python
from smolagents import ToolCallingAgent, InferenceClientModel, DuckDuckGoSearchTool

agent = ToolCallingAgent(
    tools=[DuckDuckGoSearchTool()],
    model=InferenceClientModel(),
)
result = agent.run("Search for the latest news on AI regulation")
```

## Limitations and Considerations

- **Code Execution Risk**: CodeAgent generates and executes arbitrary Python code, requiring sandboxed environments (Modal, Blaxel, E2B, Docker) for safe operation
- **Model Dependency**: Agent quality depends heavily on the underlying model's ability to generate correct, composable code
- **Lightweight by Design**: The minimal abstraction layer means advanced orchestration patterns (complex multi-agent coordination, stateful workflows) may require custom implementation
- **Sandbox Setup**: Secure execution environments require additional infrastructure configuration beyond the base library
