## Overview

OpenAI provides hosted large language model APIs that power text generation, image understanding, audio processing, embeddings, and agent-based applications. The platform offers frontier models (GPT-5.2, GPT-5, GPT-4.1) alongside specialized models for image generation, video, speech, and real-time interactions. All models are accessed through RESTful APIs with official SDKs in Python, TypeScript/JavaScript, Go, C#, and Java. [1][2]

The platform is organized around the **Responses API** (recommended for new projects) and the legacy **Chat Completions API**, with additional endpoints for embeddings, audio, images, video, fine-tuning, evaluations, and real-time WebSocket/WebRTC connections. [2]

## Core Concepts

### Responses API

The Responses API is OpenAI's recommended interface for new projects. It returns an `output` array containing text outputs, tool calls, and reasoning data. SDKs provide an `output_text` convenience property that aggregates all text results into a single string. It is not safe to assume that the model's text output is at `output[0].content[0].text`; always inspect the full output array. [3]

### Message Roles

Three message roles establish different authority levels in conversations:

- **`developer`**: High-priority instructions from the application, functioning like function definitions
- **`user`**: Lower-priority inputs from end users, analogous to function arguments
- **`assistant`**: Responses generated by the model

The `instructions` parameter provides high-level behavioral guidance and takes priority over prompt input. [3]

### Function Calling

Function calling enables models to interface with external systems. The model examines a prompt, determines if it needs to call a provided tool, and returns structured JSON with the function name and arguments. Your application executes the function and returns results to the model for a final response. The process follows five steps: send tools + prompt, receive tool calls, execute code, return outputs, get final response. [4]

### Structured Outputs

Structured Outputs guarantees model responses conform to a defined JSON schema, eliminating formatting inconsistencies and retry logic. Available via `response_format` parameter with JSON schema or through SDK integrations with Pydantic (Python) and Zod (TypeScript). Requires `gpt-4o-mini` or later models. [5]

### Embeddings

Vector embeddings measure text relatedness through vector distance. OpenAI offers `text-embedding-3-small` (1536 dimensions) and `text-embedding-3-large` (3072 dimensions), both supporting up to 8,192 input tokens. Both v3 models support the `dimensions` parameter for dimension reduction without losing concept-representing properties. [7]

## Architecture

### API Structure

The OpenAI platform exposes these API families:

- **Responses API** -- Primary text generation endpoint (recommended)
- **Chat Completions API** -- Legacy text generation endpoint
- **Embeddings API** -- Vector representation generation
- **Audio API** -- Speech-to-text (Whisper) and text-to-speech
- **Images API** -- Image generation (GPT Image 1.5) and editing
- **Video API** -- Video generation (Sora 2)
- **Files API** -- File uploads for vision, fine-tuning, and vector stores
- **Fine-tuning API** -- Model customization with training data
- **Realtime API** -- WebSocket/WebRTC/SIP for low-latency streaming
- **Batch API** -- Asynchronous bulk processing
- **Vector Stores API** -- Knowledge storage for file search
- **Evals API** -- Model evaluation and benchmarking
- **Administration API** -- Organization and project management [1]

### Streaming via Server-Sent Events

Streaming uses semantic, typed events. Key event types: `response.created`, `response.output_text.delta`, `response.completed`, `error`. Enable with `stream=True`. [8]

### Backwards Compatibility

Backwards-compatible changes include: adding new resources, optional parameters, JSON response properties, changing property order, changing opaque string formats, and adding event types. Pin model versions (e.g., `gpt-5-2025-08-07`) for consistent behavior. [1]

## Key Features and Functionality

### Text Generation

Generate text using the Responses API with multi-turn conversations. Supports `developer`, `user`, and `assistant` roles. Reusable prompt templates with placeholder variables are available via the dashboard. [3]

### Function Calling

Define functions with JSON schema; the model determines when to call them:

```python
tools = [{
    "type": "function",
    "name": "get_weather",
    "description": "Get the current weather in a given location",
    "parameters": {
        "type": "object",
        "properties": {
            "location": {"type": "string", "description": "City and state"}
        },
        "required": ["location"]
    },
    "strict": True
}]
```

Tool choice options: `auto` (default), `required`, forced function, `allowed_tools` subset. Parallel function calling supported; disable with `parallel_tool_calls: false`. Strict mode ensures schema adherence with `additionalProperties: false` required on all objects. [4]

### Structured Outputs

Use Pydantic (Python) or Zod (TypeScript) for type-safe schema enforcement:

```python
from pydantic import BaseModel

class CalendarEvent(BaseModel):
    name: str
    date: str
    participants: list[str]

completion = client.chat.completions.parse(
    model="gpt-4o-2024-08-06",
    messages=[...],
    response_format=CalendarEvent,
)
event = completion.choices[0].message.parsed
```

Use cases: chain-of-thought reasoning, data extraction, UI generation, classification. [5]

### Vision

Process images via URL, base64, or File API. Formats: PNG, JPEG, WEBP, non-animated GIF. Max 50 MB payload, 500 images/request. Detail levels: `low` (512px, 85 tokens), `high` (full resolution), `auto`. [9]

### Embeddings

```python
response = client.embeddings.create(
    input="Your text string goes here",
    model="text-embedding-3-small"
)
```

Models: `text-embedding-3-small` (1536 dims, 62,500 pages/$), `text-embedding-3-large` (3072 dims, 9,615 pages/$). Use cases: search, clustering, recommendations, anomaly detection, classification. [7]

### Realtime API

Low-latency multimodal interactions via WebRTC (browser), WebSocket (server), or SIP (telephony). Supports speech-to-speech and multimodal inputs/outputs with configurable voices:

```javascript
const ws = new WebSocket(url, {
    headers: { Authorization: "Bearer " + process.env.OPENAI_API_KEY }
});
ws.send(JSON.stringify({
    type: "session.update",
    session: { type: "realtime", instructions: "Be helpful!" }
}));
```
[10]

### Agents (AgentKit)

AgentKit provides: Agent Builder (visual canvas with templates), ChatKit (embedded frontend component), Agents SDK (custom development), and evaluation tools for performance monitoring. Supports custom tools, vector store knowledge bases, and agent-to-agent routing. [6]

## Use Cases

### Conversational AI

Build multi-turn chatbots using the Responses API with conversation state management. Use `developer` role for system behavior, `user` role for end-user messages, and conversation history for context. [3]

### Data Extraction

Use Structured Outputs with Pydantic/Zod schemas to extract structured data from unstructured text, eliminating parsing errors and retry logic. [5]

### Document Analysis

Combine vision capabilities with text generation to analyze images, PDFs, and documents. Support for base64-encoded images and File API uploads. [9]

### Semantic Search and RAG

Generate embeddings with `text-embedding-3-small` or `text-embedding-3-large` for similarity search. Cosine similarity computed efficiently via dot product on normalized vectors. Store in vector databases for retrieval-augmented generation. [7]

### Voice Applications

Build real-time voice agents using the Realtime API with WebRTC or WebSocket. The Agents SDK for TypeScript provides a recommended approach for voice agent development. [10]

## API Reference Summary

### Key Endpoints

- `POST /v1/responses` -- Create a response (primary text generation)
- `POST /v1/chat/completions` -- Legacy chat completions
- `POST /v1/embeddings` -- Create vector embeddings
- `POST /v1/audio/speech` -- Text-to-speech generation
- `POST /v1/audio/transcriptions` -- Speech-to-text transcription
- `POST /v1/images/generations` -- Image generation
- `POST /v1/files` -- Upload files
- `POST /v1/fine_tuning/jobs` -- Create fine-tuning job
- `POST /v1/vector_stores` -- Create vector store
- `POST /v1/batches` -- Create batch request
- `WSS /v1/realtime` -- Realtime WebSocket connection

### Response Properties

- `output` -- Array of content blocks (text, tool calls, reasoning)
- `output_text` -- Convenience string aggregating all text blocks
- `stop_reason` -- Why generation stopped (e.g., `end_turn`, `tool_use`)
- `usage` -- Token counts (`input_tokens`, `output_tokens`)
- `model` -- Model identifier used [1]

## Configuration and Customization

### Generation Parameters

- **`model`** -- Model ID (e.g., `gpt-5.2`, `gpt-5-mini`, `gpt-5-nano`)
- **`temperature`** -- Randomness control (0-2)
- **`max_tokens`** -- Maximum output token count
- **`top_p`** -- Nucleus sampling threshold
- **`stream`** -- Enable Server-Sent Events streaming
- **`response_format`** -- JSON schema for structured outputs
- **`tool_choice`** -- Tool usage control (auto/required/none/specific)
- **`parallel_tool_calls`** -- Enable/disable parallel function calls
- **`instructions`** -- High-level behavioral guidance [3][4]

### Rate Limiting

Response headers provide rate limit info: `x-ratelimit-limit-requests`, `x-ratelimit-remaining-requests`, `x-ratelimit-limit-tokens`, `x-ratelimit-remaining-tokens`, `x-ratelimit-reset-requests`, `x-ratelimit-reset-tokens`. [1]

### Request Debugging

Include `X-Client-Request-Id` header (ASCII, max 512 chars) for custom request tracing. Response includes `x-request-id` for support troubleshooting. `openai-processing-ms` shows processing time. [1]

## Integration Patterns

### With Vector Databases (Pinecone, Weaviate, pgvector)

Generate embeddings via the Embeddings API, store in vector databases for semantic search and RAG applications.

### With Agent Frameworks (LangChain, LangGraph, CrewAI)

OpenAI models serve as the LLM backbone for agent frameworks. Function calling enables tool integration within agent loops.

### With Observability Tools (LangSmith, Langfuse, Helicone)

Log API requests and responses for monitoring and debugging. Use `x-request-id` for request correlation.

### With API Gateways (LiteLLM, Portkey)

Route through unified proxy layers for multi-provider failover, cost tracking, and rate limiting.

## Limitations and Considerations

- **Rate limits**: Requests and tokens are rate-limited per organization/project tier
- **Model variability**: Outputs differ between model snapshots; pin versions for consistency [3]
- **Streaming moderation**: Partial completions during streaming are harder to evaluate for content policy compliance [8]
- **Structured Outputs**: Requires `gpt-4o-mini` or later; older models support JSON mode only (validates syntax, not schema) [5]
- **Image limits**: 50 MB total payload, 500 images per request for vision [9]
- **Function count**: Keep below 20 functions for higher accuracy in function calling [4]
- **Strict mode constraints**: Requires `additionalProperties: false` on all objects, all fields must be `required` [4]
